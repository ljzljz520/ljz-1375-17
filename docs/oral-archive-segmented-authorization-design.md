# 口述档案分段授权阅读系统 — 工程设计

状态：设计评审稿 v1.0（2026-10-07）
范围：口述历史/口述档案采集平台的授权治理、Web 审校、受控播放与撤权。

---

## 1. 设计目标与威胁模型

### 1.1 目标
1. 受访者的许可被**结构化绑定到「内容区间 × 内容版本」**，而不是绑定到整条音轨或整篇文稿。
2. 所有出口（音频直链、HLS/DASH 切片、字幕/逐字稿、全文搜索、导出、引用文章、纯文字模式、转码产物、缓存节点）共用**同一个授权判定边界（PDP/PEP）**。
3. 浏览器**永远拿不到受限文字与受限音频字节**；禁止「先下发再用 CSS/JS 遮盖」。
4. 撤权可局部生效，且以**节点级可验证回执**证明缓存清理进度。
5. 剪辑/再加工后，授权不自动继承，必须做区间映射验证或重新审阅。

### 1.2 非目标
- 不承诺删除访客已经离线保存的副本（只能吊销其再次获取的能力，并在法律/告知层面声明）。
- 不做基于内容的自动真实身份推断（不做去匿名化）。
- 不试图防御已合法看到内容的用户人脑记忆；只控制**系统出口的字节**。

### 13 威胁与红线
| 威胁 | 红线 |
|---|---|
| 受限文字下发到 DOM 后用 `display:none` 遮盖 | 禁止。服务端必须在序列化前剔除 |
| 受限音频整轨可访问，前端禁止 seek | 禁止。服务端只签发/输出可见区间 |
| 字幕文件含受限句、WebVTT 时间码可绕 | 字幕走同一 PDP，按可见区间重生成 |
| 搜索索引/导出包/引用快照残留受限文本 | 索引与导出物均为授权依赖产物，撤权时同步失效 |
| 旧授权时间段直接套到剪辑后的新文件 | 禁止自动套用；必须映射验证或重审 |
| 撤权后在途转码任务把受限段发布出去 | 转码产物发布前必须重新过 PDP，未通过即丢弃/隔离 |
| 用纯文字模式绕过音频许可 | 文字与音频共用同一套 interval 授权，模式不改变判定 |

## 2. 总体架构

```
                 ┌──────────────────────────────────────────┐
                 │            Web 审校台 (Review)            │
                 │  音频波形审听 · 逐字稿校对 · 概述批准      │
                 └───────────────┬──────────────────────────┘
                                 │ 保存授权/版本/审校结果
                                 ▼
   ┌──────────────────────────────────────────────────────────┐
   │                    授权服务 (PDP)                         │
   │  consent(record_id, version, interval, subject, policy)  │
   │  输入：主体/角色 + 资源区间(版本化时间码) → allow/deny    │
   └───────▲───────────────────▲────────────────┬─────────────┘
           │ 每次出口都判定     │                │ 撤权事件 (revoke)
           │                   │                ▼
┌──────────┴────────┐ ┌────────┴─────────┐  ┌──────────────────┐
│ 文稿/字幕/搜索/导出 │ │ 媒体服务 (PEP)    │  │ 撤权编排器        │
│ 服务端投影         │ │ 段拼接/签名URL    │  │ fan-out + 回执    │
└───────────────────┘ │ 时间码重映射       │  └──────────────────┘
                      └────────┬──────────┘
                               ▼
                   转码 worker / 缓存节点 / CDN
```

关键原则：**PDP 单点判定，PEP 多点执行，出口零信任**。任何一个对外输出通道都不允许自己「理解授权」，只允许向 PDP 请求判定。

## 3. 数据模型（逻辑层）

### 3.1 档案与版本
```
ArchiveRecord(id, interviewee_id, title, current_version_id, created_at)

ContentVersion(id, record_id, kind, parent_version_id,
               media_asset_id, transcript_id, editorial_state,
               created_at)
  -- kind ∈ {raw_capture, trimmed, remixed, transcoded, published}
  -- parent_version_id 记录谱系（剪辑/再加工的来源版本）
```

### 3.2 时间码区间（版本化，禁止裸秒数）
```
TimeRange(id, version_id,
          start_src, end_src,    -- 来源版本时间码（源素材坐标系）
          start_out, end_out,    -- 输出版本时间码（本版本坐标系）
          anchor,                -- 锚点：见 3.5
          confidence,            -- 映射置信度
          mapping_state)         ∈ {verified, needs_review, rejected}
```
所有授权引用的区间都**必须携带 version_id 与坐标系**。`"00:12:30"` 脱离版本没有意义。

### 3.3 受访者许可（核心）
```
ConsentGrant(id, record_id, subject_id,           -- 授权主体=受访者（或其代表）
             scope_version_id,                    -- 绑定到具体内容版本
             ranges: [TimeRangeRef...],           -- 绑定到区间
             level,                               ∈ {full, summary_only, pseudonymized, denied}
             channels,                            ∈ {audio, transcript, caption, search, export, citation, text_only}
             valid_from, expires_at,              -- 支持时间窗许可
             status,                              ∈ {active, superseded, revoked}
             supersedes_grant_id,
             legal_basis, witness, doc_ref,       -- 授权凭证与留痕
             created_by, created_at)

ConsentRevocation(id, grant_id_or_range,
                  effective_mode,   ∈ {immediate, scheduled}
                  reason, requested_by, requested_at)
```
要点：
- 许可的最小单位是 **(version, range, channel)** 的组合，不是整条记录。
- `denied`/撤权区间与正向许可同样显式存储（**deny 优先**，且在边界处闭合判定）。
- 更名/化名通过 §9 的别名层处理，不通过删改历史许可实现。

### 3.4 访问策略（阅读侧）
```
AccessPolicy(role/audience, grant_set, channel)  → Decision
  Decision = Allow(ranges, transforms[]) | Deny(ranges)
  transforms ∈ {mask_text, silence_audio, tone_beep, pseudonymize,
                gap_indicator, summary_substitute}
```

### 3.5 区间锚点（应对剪辑漂移）
区间不能只靠秒数定位。锚点用于剪辑后重新对齐：
- `anchor.audio_fingerprint`：区间内声学指纹（如若干分块的 Chromaprint 哈希）。
- `anchor.transcript_span`：区间首尾词元（token）在逐字稿中的稳定 ID。
- `anchor.speech_turn`：话轮编号 + 说话人标签。
- 映射算法先按指纹/词元对齐，再回退到时间码；置信度低于阈值 → `needs_review`，**默认拒绝**直到人工确认。

## 4. Web 审校台

### 4.1 三栏联动
1. **音频审听**：波形 + 时间标尺，区段用颜色标注授权状态（允许/化名/仅概述/撤回）。
2. **逐字稿**：词级时间码（word-level alignment），每个词元属于某个 `TimeRange`；受限段在审校台对**无审校权限者同样不可见**（审校员另有授权）。
3. **概述/批准栏**：展示自动或人工概述，受访者/馆员在此逐段批准。

### 4.2 批准语义
- 「批准概述」= 生成一条 `level=summary_only / full` 的 grant，写入版本与区间。
- 审批动作产生不可篡改的审计记录（谁、何时、对哪个版本的哪些区间、授权哪些渠道）。
- 概述与原文解耦：某区间原文被撤，公开概述若已获单独许可仍可保留（见 §10 的「可公开替代文」）。

### 4.3 前端安全约束
- 文稿通过**服务端投影（projection）**下发：后端按当前用户的 Decision 只序列化允许的词元；受限位置输出占位符 `{gap: id, reason_code}`，不含原文。
- 音频通过分段 URL / HLS 播放表下发，**播放清单本身已被裁剪**，不含受限分片。
- CSS/JS 仅做呈现（间隙提示、化名样式），不承担访问控制职责。可在浏览器 DevTools 中验证：DOM 与网络面板都不存在受限字节。

## 5. 授权判定（PDP）与统一边界

### 5.1 判定输入输出
```
decide(subject, resource(record, version, [range], channel), now)
  -> Allow(allowed_ranges, transforms) | Deny
```
规则顺序（短路）：
1. 区间匹配到 `revoked`/`denied` → 拒绝该子区间（deny 优先）。
2. 许可版本 ≠ 请求版本，且未经映射验证 → 拒绝（见 §8）。
3. 渠道不在 `channels` 内 → 拒绝（因此 text_only 不能绕音频限制，反之亦然）。
4. 时间窗外（`expires_at`）→ 拒绝。
5. 需要化名 → 允许但附 `pseudonymize` 变换。
6. 仅概述 → 在全文/音频渠道拒绝，在概述渠道允许。

### 5.2 出口清单（全部必须调用 PDP）
| 出口 | 执行方式 (PEP) |
|---|---|
| 音频直链 / 签名 URL | 签发前判定；URL 绑定 version+range+短 TTL |
| HLS/DASH manifest | 按允许区间生成 playlist；受限分片不入清单、不签名 |
| 逐字稿 / WebVTT 字幕 | 服务端投影；字幕按可见区间重新生成并重排时间码 |
| 全文搜索 | 索引按可见性分片/打标；查询时过滤；受限段不进入可命中倒排 |
| 导出（音/文/字幕包） | 导出任务逐区间判定；产物登记为授权依赖物 |
| 引用文章/外部片段 | 引用持有 `(record, version, range)` 引用而非内嵌副本；解析时实时判定；可缓存已批准的替代文 |
| 纯文字模式 | 同一 channel 判定，不豁免 |
| 转码产物 | 发布前判定（§7.3） |
| CDN/代理缓存 | 缓存键含授权维度；受限内容禁止在共享层缓存（§11） |

## 6. 受限文字与受限音频的服务端处理

### 6.1 文字
- 投影在序列化层完成（JSON/HTML 之前），受限词元**物理缺席**。
- 间隙用稳定占位符：`{{gap:g123}}`，前端渲染为「应受访者要求，此段不公开」。
- 搜索：受限区间不写入面向公众的倒排索引；或写入单独的受限索引并由 PDP 过滤。撤权时对该区间做**索引删除 + 段合并**，并返回索引节点回执。

### 6.2 音频
两种交付策略见 §7；无论哪种，输出的字节流都不包含受限声波（不是静音覆盖整轨——若整轨已下发，静音只是元数据层面的伪装，原始 PCM 仍在客户端）。

### 6.3 间隙指示与时间码重映射
- 拼接模式下输出文件被「抽掉」受限段，输出时间轴是不连续的。提供两套时间码：
  - `output_t`：用户实际播放轴（连续）。
  - `source_t`：原始素材轴（带间隙，供引用回溯）。
- 每个间隙下发 `gap_map`：`{out_start, out_end, src_start, src_end, reason_code}`。
- 播放器 seek 时把 `output_t` 经 gap_map 映射到源区间；**跳过隐藏区**：进度条不暴露隐藏段时长（可选择显示为固定宽度的「受限」标记，但不泄露真实长度/内容）。

## 7. 预生成脱敏音轨 vs 按请求拼接片段

| 维度 | 方案 A：预生成脱敏音轨 | 方案 B：按请求拼接可见片段 |
|---|---|---|
| 做法 | 对每个「受众×版本」离线渲染一条已移除/降混受限段的固定音轨，普通分发 | 清单只列允许分片，边缘/媒体服务按需取分片，用 gap_map 串联 |
| **撤权延迟** | **高（主要缺点）**：撤权后旧预生成轨仍存在于源站、CDN、节点缓存、已导出包；必须使全部副本失效并重新渲染，存在传播窗口 | **低**：撤权即时反映在 manifest/签名结果；下一次请求即拿不到受限分片；只需失效清单与分片签名，不需重新渲染整轨 |
| **缓存效率** | 高：整轨文件少、命中率高、字节范围请求友好；但缓存的是「授权固化物」，撤权代价大 | 中：分片可高命中（公共分片共享），manifest 按授权/低 TTL 缓存；需防缓存串号（缓存键必须含可见性维度） |
| **时间码重映射代价** | 离线一次性完成，重映射成本前置；但每次剪辑/撤权都要重渲染并重算 gap_map | 每次播放动态计算/取预计算 gap_map，播放逻辑复杂；跨片边界的交叉淡入/采样率对齐需实时处理 |
| 计算成本 | 离线批量、可调度；峰值低 | 边缘 CPU/清单生成压力；可对「常用授权组合」做二级预生成兜底 |
| 音频质量风险 | 渲染时统一做边界处理（淡入淡出、爆音控制），质量稳定 | 拼接边界可能产生爆音/采样错位，需要分片在帧边界切分（如 20ms AAC 帧对齐）与轻微 crossfade |
| 适配多档许可 | 组合爆炸：N 个受众许可 × M 版本需 N×M 条轨 | 天然适配：同一分片池服务多种可见性 |
| 已离线下载副本 | 无法收回（两方案相同），只能吊销再获取 | 同左，但因分片授权化，已下载的也仅限「下载当时允许」的段 |
| 推荐 | 作为**默认公开档**的加速层（公开/宽许可组合），但每次撤权必须强制重渲染+失效 | 作为**主授权边界**；A 仅作为 B 在命中特定稳定许可时的缓存优化，且缓存物带授权标签可被撤回索引追踪 |

**结论**：以 B 为安全边界（fast revocation / single PDP），以 A 为可撤回的性能缓存层；任何 A 产物都登记在「授权依赖物清单」中，撤权时必须能被枚举、失效、重渲染。绝不能让 A 成为撤权无法穿透的固化副本。

## 8. 剪辑/再加工后的授权继承

1. 新版本 `ContentVersion(parent_version_id=...)` 建立谱系。
2. 用 §3.5 锚点跑区间对齐：
   - 指纹/词元命中且落在阈值内 → `verified`，人工确认后映射 grant。
   - 区间被压缩、拉伸、跨剪辑点、只命中部分 → `needs_review`。
   - 内容实质改变（重配音、语序重排）→ `rejected`。
3. **`needs_review/rejected` 的区间默认不公开**，即使旧版本是 full 授权。
4. 审校台列出「待映射授权」清单，馆员+受访者（或其授权代表）逐条确认或重新签署，形成新的 grant（`supersedes_grant_id` 指向旧 grant，保留谱系）。
5. 禁止行为：UI 上不得出现「一键沿用全部旧授权」的默认按钮；批量沿用必须显式选择并留痕。

## 9. 受访者更名 / 化名

- 受访者持有稳定 `subject_id`；展示名是带时间轴的**别名层**：
  ```
  Alias(subject_id, display_name, valid_from, valid_to, scope_channels, kind)
    kind ∈ {legal_name, pseudonym, anonymous_marker}
  ```
- 历史已发布内容在 `valid_from` 之后的展示统一按当前策略解析为化名或「匿名受访者 N」；引用文章中已缓存的旧名通过同一解析层失效。
- 系统**不自动推断真实身份**：不做人脸/声纹与外部资料的自动比对、不把化名与可识别信息交叉关联展示。工作人员手工建立的关联仅限内部、需额外权限且全量审计。
- 更名触发的是「展示变换」，可与内容撤权组合（如某区间允许音频但要求化名）。

## 10. 引用文章与「可公开替代文」

- 引用存储为结构化引用 `Citation(record_id, version_id, range, transform_allowed)`，**不内嵌媒体字节/原文副本**；渲染时实时过 PDP。
- 撤权后引用处自动降级为：
  1. 占位 + **来源链**（指向档案目录页/档案馆藏号），或
  2. 受访者已单独授权的**可公开替代文**（summary / 重述版，有自己独立的 grant，可脱离原音长期存在）。
- 来源链始终保留（馆藏号、采访日期、版权/许可说明），不因内容撤权而抹除线索。
- 两个专题引用同一区间：两条引用都指向同一 `(record, version, range)`，撤权一次，两处同时生效；替代文按专题策略可各自配置。

## 11. 缓存、撤权编排与可证明回执

### 11.1 缓存分层与失效
```
源站授权依赖物登记表 (entitlement-derived objects):
  object_id, kind, grant/range_refs, version,
  locations: [edge_node...], state: active|invalidated|rebuilding
```
- 预生成轨、导出包、渲染好的引用快照、搜索段、缩略波形等全部登记。
- 撤权事件 → 撤权编排器按依赖图 fan-out 到：源站对象存储、转码队列、各 CDN/边缘节点、搜索索引节点。

### 11.2 节点回执（可证明进度）
- 每个节点执行失效后返回**签名回执**：
  ```
  PurgeReceipt(node_id, object_ids, purge_token,
               before_hash/version, after_state, timestamp, signature)
  ```
- 编排器汇总为进度视图：`已确认 N/M 节点；未确认节点列表与重试状态`。
- 「完成」的定义=达到回执阈值（如全部强制节点已签收），而不是「按钮已点」。
- 无回执的节点标记为**未证实**，该节点上的缓存对象视为仍可能泄露：自动将其从授权路由摘除或拉黑，直到回执到达。

### 11.3 诚实的能力边界
- UI/法务文案明确：系统可吊销访问、清理**受控节点**缓存、使旧链接失效；
- **不能声称删除访客此前已保存到本地的副本**（下载、录屏、打印）。对已签发长期下载 URL 的，尽量用短 TTL + 签发即绑定授权的方式减少此类副本。

### 11.4 撤权与在途转码任务
- 转码任务携带 `consent_snapshot(version_id, hash)`。
- worker 发布产物前：
  1. 向 PDP 重新 `decide`（防 TOCTOU：许可在任务排队期间被撤）；
  2. 比对授权快照哈希是否仍为当前；
- 若区间被撤：**丢弃或剪去该区间后重渲产物**；无法剪的（整轨重混）置隔离态，不发布，并回报事件进审计。
- 对应验收用例 AC-04。

## 12. 审计与可观测
- 所有 grant/revoke/mapping/alias/purge 动作写只追加审计日志（操作者、时间、版本、区间、凭证引用）。
- 指标：撤权→全回执耗时、`needs_review` 区间数、PDP 拒绝计数（按渠道）、缓存串号告警（不同授权主体命中同一缓存键即安全事故）。
- 定期红队测试：尝试通过字幕、搜索、导出、纯文字模式、旧直链访问受限段，应全部拒绝。

## 13. 验收用例（Acceptance Criteria）

| ID | 场景 | 期望 |
|---|---|---|
| AC-01 | **局部撤权**：受访者撤回 12:30–14:00 的音频+文字，其余仍公开 | 该区间：播放清单消失、文稿为占位、搜索不可命中、导出/引用降级；其余区间正常；gap_map 正确 |
| AC-02 | **受访者更名**：事后要求化名为「老木匠」 | 所有渠道（含旧引用缓存、字幕署名）展示更新；真实身份不被系统自动推断或关联暴露；审计可查 |
| AC-03 | **两个专题引用同段**：专题甲、专题乙引用同一 30 秒区间 | 撤权该区间后，甲、乙两处同时失效并降级到来源链/替代文；不存在第二处残留副本 |
| AC-04 | **撤权后转码才完成**：转码任务排队时区间被撤 | worker 发布前重判失败 → 产物不含该区间或被隔离；受限段绝不上线；事件入审计 |
| AC-05 | **播放跳到隐藏区**：用户拖动进度条经过受限段 | 播放器越过隐藏区间，落在下一个可见点；隐藏段真实时长/内容不通过 UI 或网络泄露；字幕同步跳过且时间码连续 |
| AC-06 | **纯文字模式绕权尝试** | 与音频模式同一判定，受限文字同样缺席（物理不在响应体中） |
| AC-07 | **CSS 遮盖审查** | DevTools 的 Elements 与 Network 中均不存在受限原文/受限音频分片请求 |
| AC-08 | **剪辑后沿用旧授权** | 未映射验证的区间默认拒绝；无「一键全沿用」；重审后新 grant 与谱系正确 |
| AC-09 | **缓存清理证明** | 撤权进度页显示每个节点签名回执；未回执节点被标记并摘除；文案不声称能删除访客本地副本 |
| AC-10 | **直链与签名 URL** | 撤权后旧 URL 立即失效（短 TTL/签名绑定 version+range）；改 URL 参数扩大区间被拒 |
| AC-11 | **许可到期（时间窗）** | `expires_at` 过后自动转入拒绝，无需人工撤权 |
| AC-12 | **来源链与替代文** | 降级页保留馆藏号/来源链接；若存在已授权替代文则展示替代文，且替代文不依赖原音 |

## 14. API 草案（要点）

```
POST /pdp/decide
  {subject, record, version, ranges:[{start,end,coord}], channel, now}
  -> {decision, allowed_ranges, transforms, gap_map_ref}

GET  /media/{record}/manifest?version=&subject_token=
  -> 裁剪后的 HLS/DASH（仅可见分片 + gap 标记）

GET  /transcript/{record}?version=
  -> 服务端投影后的词元序列（受限处为 gap 占位）

GET  /search?q=...
  -> 仅命中可见区间，高亮不含受限词

POST /review/{record}/{version}/grant      # 审校批准 -> 生成 grant
POST /review/{record}/{version}/revoke     # 局部/整体撤权 -> 触发编排
GET  /revoke/{event_id}/progress           # 节点回执进度

POST /media/remap    # 剪辑后区间锚点映射 -> verified/needs_review/rejected
POST /transcode/callback   # worker 发布前强制携带 consent_snapshot 复核
```

## 15. 关键取舍小结
- **安全边界选「按请求拼接（B）」**，预生成脱敏轨（A）只作带授权标签、可枚举失效的缓存加速。
- **授权绑版本+区间+锚点**，秒数本身不承载授权。
- **一个 PDP，所有出口零信任**：音频、字幕、搜索、导出、引用、纯文字、转码、缓存同一边界。
- **撤权的成功用节点签名回执定义**；对访客本地副本诚实声明能力边界。
- **剪辑不继承授权，映射不上就默认拒绝**。
- **更名走别名层与展示变换，绝不做自动身份推断。**
